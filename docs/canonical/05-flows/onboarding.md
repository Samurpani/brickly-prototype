# Flow: Developer Onboarding

**[MVP·concierge]** — v1 onboarding is founder-led, high-touch, 1–2 founding members per week. Source: `source/bricly-flow-onboarding.md` (pre-flow + 12-step ideal self-serve flow).

## v1 concierge onboarding (weeks 1–2 per member)

1. **Pre-flight** (before the call): member sends unit schedule (any format — Excel, PDF price list), team roster, project media. Concierge normalises units to the import CSV shape.
2. **Provisioning**: workspace created, developments + units imported (concierge-run import; AI-assisted CSV mapping is [v1.1]), team accounts + roles set (owner / manager / rep), existing leads/opps imported if migrating.
3. **Onboarding call (1–2h)**: walk the team through board, opportunity journey, units, calendar; set up WhatsApp connection for reps; configure notification prefs and approval gates.
4. **First-week shadow**: concierge watches usage, fixes data, answers via direct WhatsApp support line.
5. **Success gate** (activation criterion from `02-mvp-scope.md` §2): team in CRM, project + units loaded, pipeline live with real opportunities.

Runs alongside the **Launch Package** flow if the member bought activation (`launch-package.md`) — onboarding gets the OS live; the launch package gets the project market-ready.

## Deferred from the ideal flow

Self-serve signup + guided setup wizard, AI unit-schedule ingestion (CAD/PDF → structured units), automated team invites, sample-data sandbox, in-product checklists/tours — **[v1.1+]**. The ideal flow becomes relevant at commercial launch (~M6) when concierge onboarding stops scaling.

## Commercial context (v19 figures)

Onboarding is a paid line item (€5k) separate from activation packages; see `08-business/` → `source/bricly-pricing-plan-final.md`. Pace of 1–2/week is set by concierge fulfilment capacity, not sales.
