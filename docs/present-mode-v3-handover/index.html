Present Mode v3: developer handover

This document tells the development team how Present Mode v3 operates. It shows each screen, the steps to operate it, the rules that control it and the code that makes it. Use this document with the prototype and the source code.

Welcome→Gallery→Development slideshow→Unit page→Compare→Secure→Thank you→Checkout→Buyer link

1 · About this documentPurpose, audience and conventions.

Purpose

Use this document to build the production version of Present Mode. It gives the behaviour, the data and the rules of the prototype.

Audience

Front-end developers, back-end developers, QA engineers and product designers.

Live prototype

prototypes/v3/Bricly_OS_Prototype_v3.html. In the sidebar, click Present.

Writing standard

This document uses ASD-STE100 Simplified Technical English. Procedures use the imperative. One sentence gives one instruction. Each term has one meaning.

Conventions

  • Bold text is a label on the screen.
  • Code text is a file, a function, a state key or a value.
  • Key is a keyboard key.
  • NOTE gives information. CAUTION tells you about a risk to data or behaviour. REQUIREMENT is a rule that production must keep.

2 · System overviewWhat Present Mode does and how a user gets into it.

Present Mode is a full-screen sales presentation. A sales representative (the rep) uses it with a buyer, in a meeting or on a shared screen. The rep shows developments, then residences (units). The buyer selects units. The rep compares the units, holds one, reserves it and books the signing. After the meeting, the rep sends a link to the buyer.

Each development has its own brand: colours, display font and logo. The presentation loads this brand when it shows the development.

Users

UserWhat the user doesWhat the user must not see
RepOperates the presentation. Links the buyer to the CRM. Sends the link.No limit.
BuyerLooks at the screen. Selects units. Types own details on the Secure step. Opens the buyer link later.CRM lists, other buyers, buyer signals, insights.
Live viewerFollows the presentation in a second browser. Cannot click.Checkout, insights, partner screens.
Partner (broker)Presents with a partner link. Registers a client.All CRM data.

Module registry

Each module registers its screens and actions on the core object P = window.PV3.

KeyTypeUse
P.screens[name]function → HTML stringDraws one screen. The value of S.screen selects the screen.
P.actions[name]function(value, element, event)Runs when the user clicks an element with data-a="name". The value comes from data-v.
P.actions['in:'+field]function(value)Runs on input in an element with data-f="field".
P.after[]function(root, state, why)Runs after each render. Use it to attach behaviour (drag, carousels, animations). why is 'resize' on window resize.
P.keys[]function(event) → trueKeyboard handlers. Return true to stop the event.

Render cycle

  1. An action changes the state object S.
  2. The action calls P.render() (or P.go(screen) to change the screen).
  3. render() keeps the scroll position and the focus.
  4. render() calls P.screens[S.screen]() and puts the HTML into the shell #pv-shell.
  5. If the screen changes, the old nodes stay for a short time and fade out (class pv-leave).
  6. Open floating panels with the same data-pk stay open with no animation. Closed panels animate out (class pv-panel-out).
  7. render() runs all P.after functions.
NOTE: Some changes do not use a full render because a full render would restart animations. Slide changes (P.goSec), carousel moves (P.carouselTo), the price slider and the filter tiles change the DOM directly.

5 · Start and galleryFrom the sidebar to the selected developments.

5.1Welcome and loading

P.screens.welcome, P.screens.loading, intro() in present-v3.js


What it shows

The welcome screen shows the seller name (white label). The loading screen shows the number of developments and available residences. The background is a moving light field (P.aurora()).

Sequence
  1. The welcome screen shows for 2.3 s.
  2. The loading screen shows for 1.9 s. The progress bar fills.
  3. The text moves up and fades. The background expands and dissolves into the gallery.
Operate
  1. To skip, click Skip or press Esc.
Rules
  • With Quick start on, the times are 1.1 s and 1.0 s.
  • A partner link shows the partner name and "Presenting <seller>".
  • "Powered by Bricly" is a small credit at the bottom left.

5.2Showcase

P.screens.gallery, carousel(), P.carouselTo() in present-v3-gallery.js

What it shows

One large development card in the centre. Part of the next card shows at each side. The card shows the name, the location and the lowest available price.

Operate
  1. To go to the next development, click the right arrow or press →.
  2. To add the development to the presentation, hover the card and click ✓.
  3. To open the quick view, click the card or ↗.
  4. To see all developments as a grid, click the grid icon.
  5. To start, click Present selection.
Rules
  • Present selection is disabled while the queue is empty.
  • The carousel keeps 3 cards on each side in the DOM, so a move does not render again.
  • Fast clicks queue up. The carousel goes to the last target.

5.3Filters (tile view)

fEnter(), fExit(), ftiles(), camera(), P.fPreview() in present-v3-gallery.js

What it shows

When the filter panel opens, the showcase zooms out into tiles of all developments. Developments that do not match become blurred, grey and small.

Operate
  1. Click the filter icon at the top left.
  2. Set Location, Bedrooms, Property type (more than one), Price range and Features.
  3. To apply, click Show N matching developments. You can also press Esc or click outside the panel.
  4. To apply and go to one development, click its tile.
Rules
  • The tiles update during the price slider drag. The filter changes only when you release the slider.
  • A tile that does not match does nothing when you click it.
  • After you apply, the view goes to the first match. If you clicked a tile, it goes to that development.
  • The price filter compares all developments in one currency (the display currency, or EUR).

5.4Queue and settings

queuePanel(), settingsPanel(), P.prefsRows()


Queue
  1. Click N in presentation.
  2. Drag a row to change the order.
  3. Click × to remove a development.
Settings
  • Theme: Dark, Light or System.
  • Grid size.
  • Prices in: Local, €, $, £ or AED. Local uses the currency of each development.
  • Language: labels for the buyer (EN, FR, DE, IT, 中文).
  • Quick start: shorter welcome and loading.
  • Partner presentation link and Presentation insights (rep tools, see section 9).
NOTE: Ask Bricly AI is a simulation. It reads words in the question and sets the filters.

5.5Quick view

overview(), A.ovOpen, A.ovClose in present-v3-gallery.js

What it shows

Name, lowest price, facts, description, amenities, an image gallery and the action bar (Present now, Add to presentation).

Open sequence
  1. The card image grows to full screen.
  2. The image becomes blurred and dark.
  3. The details come in, one after the other.
Close sequence
  1. The text fades out.
  2. The blur goes away.
  3. The image shrinks into the card. If the gallery image is different, it changes to the card image during the shrink.
Rules
  • The background always shows the active gallery image.
  • The morph moves a real element (left, top, width, height). Both the element and the card use cover, so the crop is the same at each end.

6 · Development slideshowFull-screen slides. No scrolling.

6.1Slideshow navigation

P.goSec(), slide(), BODY, P.navBar() in present-v3-brochure.js

Operate
  1. To go to the next slide, press ↓, →, Page Down or Space.
  2. To go back, press ↑, ← or Page Up.
  3. You can also use the mouse wheel, a swipe or the up and down buttons at the bottom right.
  4. To go to a page, open the page switcher in the top bar.
  5. To close Present Mode, click × at the top right.
Rules
  • Only one slide shows at a time. The old slide moves away and fades. The new slide plays its entrance.
  • A new move is not possible for 650 ms after a move.
  • The mouse wheel needs 280 ms of no input before the next move. This stops the trackpad from skipping slides.
  • A list that can scroll (availability, location points) uses the wheel first.
  • The × button shows on every screen. The session is saved.

6.3Content slides

intro(), lifestyle(), amenities(), location(), ownership(), residences(), walkthrough(), gallery(), plans()

Introduction

Title, text and a large image. The image opens from the side of the text. The title rises word by word.

Lifestyle

  1. Drag or flick the cards.
  2. Or click the arrows. The counter shows 01 / 04.

Each card comes in after the one before it.

Amenities

  1. Click an amenity in the list. The slider moves to its render.
  2. Or drag the slider, or click the arrows.

Each amenity has a render and one line of text for the rep. The data is in amenityItems().

Location

Points of interest on the left. Hover a point to show its category colour. The map is a static image now.

REQUIREMENT: Production must link each point to a map pin. The map must move and zoom.

Payment & ownership

Left: the payment plan with an amount for each stage. Right: Timeline and Details of the Project. The right side comes in after the left side.

  • Timeline from commerce().timeline. States: done, now, empty.
  • Deposit protection, service charges, estimated yield, developer, track record.

Residences

Groups by property type: Maisonettes, Apartments, Penthouses, Duplexes. Each group has a render, the number available and the lowest price for each bedroom count. A click does nothing.

Walkthrough

A film of still images. Each image shows for 4.5 s with a slow zoom. Click pause to stop it.

NOTE: This slide holds the place for a 3D tour.

Gallery

  1. Click an image to open the lightbox.
  2. Press ← or → to go through the images.

The last tile shows "+N" if there are more images.

Plans

One typical plan for each bedroom count, with the room schedule. View N available opens the availability list with that bedroom filter.

NOTE: Renders show the label Artist's impression. Plans show Indicative plan. Views show Indicative view. This is a legal requirement in the EU, Malta, Dubai and Florida.

8.2Compare

P.screens.compare, P.cmpTable() in present-v3-checkout.js

Tabs

8.3Secure your residence

secure(), A.choose, A.book in present-v3-checkout.js

Operate
  1. On the compare page, click Choose this one on a unit.
  2. Step 1: click Hold for 48 hours.
  3. Step 2: the buyer types name, email and phone, and sets consent. Click Save buyer.
  4. Step 3: click Send reservation agreement.
  5. Step 4: select a day and a time. Click Book contract signing (USD markets) or Book promise of sale (Malta).
  6. Step 5: click Send the proposal.
Rules
  • Step 3 needs a hold and a buyer.
  • Step 4 needs a buyer.
  • Step 2 shows no CRM list, because the buyer can see this screen. If the session started from an opportunity, step 2 is already done.
  • Step 4 sets the opportunity stage to Contract Booked and the next action to the signing.
  • Step 5 goes to the thank-you screen (the privacy gate).
  • Each step writes to the opportunity activity.

8.4Thank you and checkout

P.screens.thanks, P.screens.checkout, linkBox(), shareBox(), ensureOutput()

Thank you (privacy gate)

The buyer can see this screen. It shows the logo of the developer, the buyer name and the selection count.

  1. Turn the screen away from the buyer.
  2. Click Screen turned away · continue.
CAUTION: Checkout shows CRM data. Do not show checkout to the buyer.
Checkout: link
  1. Select Opportunity, Contact or New buyer.
  2. Find the record and click it, or type the new buyer details.

A new buyer makes a contact and an opportunity. The selection, finishes and session go into the opportunity.

Right side (rep only)
  • The selection and the combined value.
  • Units held in this presentation, with Send reservation agreement.
  • Buyer signals: time on each unit, opens, compares, finish, hold, longest slides, focus.
Checkout: share
  1. Copy the link, or send by WhatsApp or email, or make a PDF.
  2. Select the link expiry: 7, 14 or 30 days.
  3. Set Show prices and Include the comparison.
Rules
  • The link is made automatically when an opportunity is linked.
  • When the selection changes, a new link is made.
  • Units that are not available at that time are not in the link. A warning shows their IDs.
  • WhatsApp and email stay disabled until consent is recorded.
  • The engagement line shows when the buyer opened the link.

8.5Buyer link

P.screens.buyer, engagement in trackBuyer()

  • Units by development, in the brand of each development.
  • Price in the currency of the market, payment plan, finish, plan.
  • The comparison (optional).
  • Prices valid until and the contract disclaimer.
  • Print / Save PDF.
Rules
  • After the expiry date, the link shows "This selection has expired".
  • The page records each open and the time on each unit. The rep sees this in checkout.
  • The page uses the language of the presentation.
