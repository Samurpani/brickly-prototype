Unit renders, views and finishes

Prototype: Bricly OS v3 · Language: ASD-STE100 Simplified Technical English · Date: 10 November 2026

Open the live v3 prototype Step-by-step review page Screenshot script (capture.cjs)

1. Purpose

This document tells developers how to build unit renders and views.

A unit can have many renders. Each render shows one room. A room can have different renders for each layout, finish pack and style. The user tags each render with these values. Present Mode then shows the correct render for the buyer's choice.

All unit imagery comes from the development content in Edit development. Present Mode does not have hard-coded imagery.

NOTEA user does not need to upload a render for every combination. When a combination has no render, Present Mode keeps the default render for that room.

5. Procedure 1 · Set up the interiors catalogue

Do this procedure one time for each development.

  1. Open Developments → a development → Edit → Finishes, interiors & extras.Result: The Interiors catalogue shows rooms, layouts and styles (Figure 1).
  2. Add or rename the rooms. For each room, set the rule.Result: Each unit shows only the rooms that apply to it.
  3. Add the layouts. Set the rule and the price for each layout.Result: The default layout has no price.
  4. Click a finish pack. Select the styles that the pack offers.Result: Present Mode offers only these styles with the pack (Figure 2).
CAUTIONWhen the user removes a room, layout or style, Bricly removes that tag from all renders. The toast tells the user how many renders changed.

6. Procedure 2 · Add renders to a unit

  1. Open Edit development → Units & availability. Click a unit (Figure 3).Result: The unit drawer opens.
  2. Click the Renders tab.Result: The tab shows the buyer preview bar and one row per room (Figure 4). A green frame shows the renders that a buyer sees for the current choice.
  3. In the preview bar, select a layout, finish or style.Result: Rooms that have no render for this choice show a blue note (Figure 5). The buyer keeps the default render in that room.
  4. In a room row, click + Upload. Select one or more images.Result: The tagging sheet opens (Figure 6). The room and the preview choices are filled. Tags from the filename are filled.
  5. Select Applies to. The default is all units of the same type.Result: The render applies to this scope.
  6. Check the tags. Click Add.Result: The render shows in the room row (Figure 7). The render is in the draft.
  7. To change a render, click it.Result: The asset drawer opens (Figure 8). The user can change the room, tags, scope, alt text and cover.

7. Procedure 3 · Add views

  1. In the unit drawer, click Views.Result: The tab shows the views for this unit (Figure 9).
  2. Click Upload views. Set the direction, the room it is seen from and the floor range.Result: The view shows on the units in scope and on the floors in range.
  3. To use a view from the library, click Link to this unit.Result: The view shows on this unit.

8. Procedure 4 · Bulk upload

  1. Open Upload history. Drop many files.Result: Bricly reads each filename (Figure 10). For example, kitchen_dusk_coastal_2-bed.jpg becomes Kitchen, Dusk, Coastal, all 2-bed units.
  2. Find files with no room in the name.Result: These files go to Media with no room. The user tags them in Media.

9. Procedure 5 · Publish

  1. Open Review & publish.Result: Must-fix items block publishing (Figure 11). Every image must have alt text. Bricly writes alt text for tagged uploads.
  2. Fix each item. Click Publish.Result: Present Mode shows the new content (Figure 12).

10. Procedure 6 · Present Mode

  1. Open a unit in Present Mode. Click Renders.Result: The first room with renders shows (Figure 13).
  2. Click the layout, finish and style chip at the bottom left.Result: The panel shows only options that have renders (Figure 14). A group with one option does not show.
  3. Select an option. Go to a room.Result: The room shows the render for that option (Figure 15). The price on the card includes the finish.
  4. Go to a room with no render for that option.Result: The room keeps the default render (Figure 16).
  5. Click Views, then Finishes.Result: Views show for this unit and floor (Figure 17). All finish packs show (Figure 18).
  6. Click Add to selection.Result: The selection keeps the layout, finish and style (Figure 19).

11. Rules

11.1 Render selection

Function: UM.pick(content, unit, room, choice). Bricly uses these steps for each room:

  1. Find all renders with this room that apply to the unit.Scope order: unit, then unit type, then whole development.
  2. For layout, finish and style: if no render has a tag for the chosen value, use the default value.This keeps the room the same when no render exists.
  3. Keep renders whose tags match the value or are empty. If none match, ignore style, then finish, then layout.
  4. Keep only the highest scope. Put exact tag matches first.These renders are the angles in the room carousel.
  • The Renders tab shows only when the unit has one or more rooms with renders. The Views tab shows only when the unit has views.
  • The picker shows a value only when it is the default or a render has its tag (UM.axes).
  • The Finishes tab shows all packs. The buyer can select a pack that has no renders.
  • Rooms and layouts with a rule show only on units that match the rule (UM.fits).

11.2 Filename tags

Function: UM.guess(content, units, filename). Bricly splits the name at non-letters. It matches each part to room names and aliases, pack names, style names, layout names, unit types and unit references. “view”, “outlook” or “vista” makes the file a view. Direction words and abbreviations (N, NE …) set the direction. The user checks the tags before saving.

12. Data model

All data is in the development content. Edits go to the draft. Publish copies the draft to live.
