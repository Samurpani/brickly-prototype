Buyer proposals: admin standard, brand, rep send and buyer page

Prototype: Bricly OS v3 · Language: ASD-STE100 Simplified Technical English · Date: 13 November 2026

Open the live v3 prototype Open a buyer proposal Product plan Screenshot script (capture.cjs)

1. Purpose

This document tells developers how to build buyer proposals. A buyer proposal is a private web page for one buyer. It shows the homes the buyer is interested in, with the developer's brand.

The account admin sets the rules and the brand one time. The rep does not design the page. The rep confirms the homes and the message, then sends the link.

NOTEIn the prototype, the standard and the brand are stored in localStorage. In the product, store them on the account. Store each sent proposal as an immutable snapshot.

5. Procedure 1 · Set the brand

  1. Open Settings → Proposal page.Result: The status bar shows the published version (Figure 1).
  2. In Brand, select Company brand.Result: The editor shows the logo, 7 colours, 2 fonts, a live preview and readability checks (Figure 2).
  3. To change the logo, click Upload logo. Use SVG, PNG or WebP, 300 KB maximum.Result: The preview shows the new logo. Use a text logo removes it.
  4. To change a colour, use the colour well or type a hex value. Press Tab.Result: The preview and the readability checks update.
  5. To change a font, select a font from the list, or click Upload font. Use WOFF2, WOFF, TTF or OTF, 500 KB maximum.Result: The sample line shows the font.
  6. Select a development in the list.Result: The editor shows that development's kit (Figure 3).
  7. If the development has no project brand, select Use the company brand.Result: The development uses the company colours and fonts. Its name is the logo (Figure 5).
WARNINGDo not let a brand with unreadable colours go live. Each check must be 4.5:1 or more (WCAG AA). If a check fails, the brand list shows Check and Publish is disabled (Figure 4).

6. Procedure 2 · Set sections and rules

  1. In Template, select a template.Result: The card shows In use. Templates marked Coming soon are disabled.
  2. In Sections, set each section to Always, When there's data or Off (Figure 6).Result: The status bar shows Draft and the number of changes. Required sections show Always · required.
  3. In Investment figures, select the buyer types that see rent, yield or value figures (Figure 7).
  4. In Reservations, select what buyers can do and who gets the requests (Figure 8).
  5. In Sending, select Rep approves each proposal or Send automatically (Figure 9).
  6. In Link and privacy, set the expiry, prices, passcode and tracking (Figure 10).
  7. In Legal footer, edit the text.
  8. Look at Development readiness (Figure 11).Result: Each development shows missing content. A missing item hides its section. It does not stop a send.

7. Procedure 3 · Publish the standard

  1. Click Preview draft.Result: A buyer proposal opens in a new tab with the draft applied (?std=draft).
  2. Click Publish vn.Result: A drawer lists each change (Figure 12).
  3. Click Publish vn in the drawer.Result: New proposals use the new version. Sent proposals keep their version. Versions shows the entry (Figure 13).
  4. To stop, click Discard.Result: The draft is deleted. The published version does not change.

8. Procedure 4 · Rep sends a proposal

  1. Open an opportunity that has homes.Result: The banner Proposal ready for … shows (Figure 14). If sending is automatic, the banner says when it will send.
  2. Click Review and send.Result: The drawer shows 1 Homes, 2 Message and Set by your admin (Figure 15).
  3. Remove a home with ×, or add a home with + Add a home.Result: If the rep did not edit the message, the message updates.
  4. Edit the message. Keep it to 80 words or fewer.Result: The word count shows. Send is disabled above 80 words.
  5. Click Preview.Result: The buyer page opens with this buyer, these homes and this message.
  6. Click Send on WhatsApp (or Send on email).Result: The issue is added to Shared with client. The banner goes away.
CAUTIONThe rep cannot change the template, brand, sections, prices or legal text. If content is wrong, fix it at the source (unit record, development, Settings).

9. Procedure 5 · Buyer opens the proposal

9.1 Access and intro

  1. The buyer opens the link.Result: If a passcode is on, the passcode screen shows (Figure 16). Any 4 digits work in the prototype.
  2. The intro plays for about 2 seconds, then the page opens. A tap skips it (Figure 17).Result: On a return visit, the intro says Welcome back and is shorter.

9.3 Development and home panels

  1. The buyer clicks a development card.Result: A side panel opens in the development's brand. Tabs: Overview, Amenities, Location, Progress, Your homes (Figure 26).
  2. The buyer clicks a home, or a home in the switcher at the top.Result: The home panel opens. Tabs: Overview, Renders and views, Floor plan, In the building, Payment plan, Investment or Value (Figures 27–30).
  3. The buyer clicks a tab.Result: The panel scrolls to that section. The tab line follows the scroll.

9.4 Reserve and next step

  1. The buyer clicks Reserve this home (home panel, next step or floating button).Result: The reserve sheet shows 4 steps and a short form (Figure 33).
  2. The buyer clicks Send reservation request.Result: The confirmation shows (Figure 34). The home shows Reservation requested. The rep (or sales manager) gets a task. The home is not reserved automatically.
  3. When the home is reserved, the next step shows Book your promise of sale (Figure 35).

10. Rules

10.1 Brand

  • The company kit frames the page: intro, cover, letter, compare, trust, next step, footer, top bar.
  • Each development box, panel and reserve sheet uses that development's kit. If own is false, use the company kit with the development name as a text logo.
  • A kit maps to tokens with PROPOSAL_STD.tokens(kit). Templates read tokens only. Never hard-code a colour or font in a template.
  • --on-accent is white or the text colour, whichever has more contrast on the accent.
  • Readability: text on background, secondary text, button text and text on cards must each be 4.5:1 or more. A failing kit blocks publish.
  • Fonts: a listed name loads from Google Fonts. An uploaded file loads with @font-face. In the product, host font files on your CDN and subset them.
  • Source of the first values: Company profile logo, and New development setup → Brand uploads (logo, colour values, fonts, guidelines).

10.2 Sections

StateRule
AlwaysShow the section.
When there's dataShow the section only if its data exists. Example: no profile on the opportunity → hide Buyer profile.
OffDo not show the section.
RequiredCover, Your selection, Your next step, Floor plan, Payment plan, Legal footer. Cannot be off.

Investment figures show only for the buyer types in investFor. Growth buyers see value per m² since launch, not rent. If prices are off, all prices and payment amounts show Price on request and price rows leave the comparison.

10.4 Link

  • Token: 128-bit random, base62. One token for each recipient. Never derive it from IDs.
  • Expiry from the standard (14, 30 or 60 days). The rep can renew or revoke in Shared with client.
  • Headers: noindex, nofollow, Referrer-Policy: no-referrer. No third-party scripts.
  • Preview card: og:title with the first name only, and a 1200 × 630 image. No price, no surname.
  • Tracking: first-party only. Show the notice in the legal footer. If tracking is off, send no events.

13. Build order

  1. Data: ProposalStandard, BrandKit, ProposalIssue, ProposalEvent. Seed brand kits from Company profile and New development setup.
  2. Settings → Proposal page with draft, readability checks and publish. Owner and manager only.
  3. Token service: kit → tokens, on-accent, font hosting.
  4. Buyer page renderer from an issue snapshot. Start with Signature. Server-render the first view for speed.
  5. Rep send drawer and the trigger (appointment completed, enquiry logged).
  6. Link service: token, expiry, revoke, passcode, headers, preview card.
  7. Events back to the opportunity timeline and the rep notifications.
  8. Reservation request → task for the rep or the sales manager → hold follows Approvals.
